# AFACI Mobile — React Native

Мобильный клиент AFACI для Android: React Native 0.88, Expo 58, TypeScript
strict и Expo Router. Исходники, нативный Android-проект и конфигурация
находятся в корне этого репозитория.

Flutter-клиент удалён, каталог `rn/` расформирован: приложение живёт в корне.
План и статусы этапов — в [`plan/mobile.md`](../plan/mobile.md).
Правила дизайна — [docx/mobile/DESIGN.md](../docx/mobile/DESIGN.md);
для UI использовать gluestack-ui v5 и профильные навыки этой библиотеки.
Проектный документ подпроекта — [docs/mobile/README.md](../docs/mobile/README.md).

## Требования

- Node 22 LTS, версия пинится в `.node-version`. В каждом новом терминале:
  `eval "$(fnm env)"`, затем `fnm use 22`.
- JDK 17 (`JAVA_HOME`), Android SDK 36.
- Для текущего QA на Apple Silicon установлен Android Emulator 37.2.13.
- Основной AVD — `afaci_qa_stable`: Android 36, Google APIs, ARM64,
  4 ГБ RAM, четыре ядра, аппаратный GPU, холодная загрузка без Vulkan.
  Старый `afaci_rooted` и его данные сохранены для альтернативного HTTPS-сценария.

## Запуск

Команды выполняются из `afaci_mobile`. По умолчанию приложение обращается
к локальному backend на `http://10.0.2.2:8000`: `10.0.2.2` внутри Android
указывает на хост. На самом хосте API доступен по `http://127.0.0.1:8000`.
Клиент сам добавляет `/api/v1` к путям; базовый адрес задаётся без этого префикса.
Для другого адреса задайте `EXPO_PUBLIC_API_URL` перед запуском Metro;
значение читает `src/shared/api/client.ts`.

Для локального HTTP не нужны `adb root`, системный CA, правка hosts и
`dev-emulator.sh`. Для HTTPS `api.foodcraftsl.lab` используется
[отдельная подготовка](#альтернатива-https-dev-стенд).

Что должно работать одновременно:

| Компонент         | Как проверить                                                            |
| ----------------- | ------------------------------------------------------------------------ |
| Локальный backend | `curl -fsS http://127.0.0.1:8000/api/v1/regions` — ответ API             |
| Эмулятор          | `adb devices` — устройство в состоянии `device`                          |
| Metro             | `curl -fsS http://localhost:8081/status` — `packager-status:running`     |
| Debug APK         | `adb shell pm list packages \| grep afaci` — `kg.afaci.afaci_mobile.dev` |

### 1. Подготовить терминал

```bash
cd /Users/erikomaraliev/Documents/Development/python/afaci_project_intelect/afaci_mobile
eval "$(fnm env)"
fnm use 22
export JAVA_HOME=/Library/Java/JavaVirtualMachines/temurin-17.jdk/Contents/Home
export ANDROID_HOME="$HOME/Library/Android/sdk"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$ANDROID_HOME/emulator:$PATH"
npm install
```

Подготовка Node и Java нужна в каждом новом терминале, используемом для
Metro или сборки. Локальный backend запускается по
[инструкции backend](../docs/backend/README.md#запуск).

### 2. Запустить эмулятор

В отдельном терминале:

```bash
emulator -avd afaci_qa_stable -no-snapshot -gpu host -feature -Vulkan
```

Дождитесь рабочего стола Android и оставьте терминал открытым. Проверки:

```bash
adb wait-for-device
adb shell getprop sys.boot_completed   # ожидается 1
adb devices
```

Если AVD ещё нет, создайте его в Android Studio → Device Manager:
Google APIs / ARM64 / SDK 36, имя `afaci_qa_stable`, RAM 4096 МБ,
четыре ядра, аппаратный GPU. Список AVD: `emulator -list-avds`.

Если подключено несколько устройств, задайте
`export ANDROID_SERIAL=emulator-5554`, подставив serial из `adb devices`.
На новом AVD нужно войти в приложение отдельно; учётные данные в репозитории
не хранятся.

### 3. Собрать и установить APK

Сборка нужна при первом запуске и после изменения нативных зависимостей или
конфигурации (`app.config.ts`, `plugins/`, `android/`):

```bash
npm run android -- --device emulator-5554
```

Expo CLI может завершиться ошибкой
`No development build (kg.afaci.afaci_mobile) for this project is installed`
после установки APK. Проверьте установленный пакет и запустите его командой
`npm run android:launch`; подробности — в
[диагностике](#сборка-падает-на-no-development-build).

Уже собранный debug APK можно установить на новый AVD без повторной сборки:

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

### 4. Запустить Metro и приложение

В подготовленном терминале:

```bash
npm start
```

В другом подготовленном терминале:

```bash
npm run android:launch
```

Запускается пакет `kg.afaci.afaci_mobile.dev`. Debug- и release-сборки
могут стоять на устройстве одновременно благодаря суффиксу `.dev`.

### Быстрый запуск, когда всё уже установлено

Локальный backend должен отвечать на `127.0.0.1:8000`.

```bash
# терминал 1: эмулятор
emulator -avd afaci_qa_stable -no-snapshot -gpu host -feature -Vulkan

# терминал 2: Metro
cd afaci_mobile
eval "$(fnm env)"
fnm use 22
npm start

# терминал 3: приложение
cd afaci_mobile
npm run android:launch
```

### Альтернатива: HTTPS dev-стенд

Для `https://api.foodcraftsl.lab` нужны hosts и системный CA Caddy.
Используйте Google APIs / userdebug; Google Play-образ не даёт `adb root`.
Сохранённый AVD `afaci_rooted` запускается так:

```bash
emulator -avd afaci_rooted -writable-system -no-snapshot
```

После каждого запуска этого AVD:

```bash
adb wait-for-device
adb root
adb wait-for-device
./scripts/dev-emulator.sh
adb shell ping -c 1 api.foodcraftsl.lab   # ожидается 10.0.2.2
```

Metro для этого подключения запускается с явным адресом API:

```bash
EXPO_PUBLIC_API_URL=https://api.foodcraftsl.lab npm start
```

`dev-emulator.sh` прописывает hosts и устанавливает корневой CA в системное
хранилище Android. Подготовка действует до перезагрузки AVD; подробности —
[«Dev-стенд из эмулятора»](#dev-стенд-из-эмулятора).
Для локального HTTP этот сценарий не требуется.

## Диагностика

### Экспресс-проверка локального запуска

```bash
curl -fsS --max-time 5 http://127.0.0.1:8000/api/v1/regions
curl -fsS --max-time 5 http://localhost:8081/status
adb devices
adb shell getprop sys.boot_completed
adb shell pm list packages | grep afaci
```

`127.0.0.1` в Android — сам эмулятор. Поэтому API-клиент использует
`10.0.2.2:8000`, а проверка с хоста — `127.0.0.1:8000`.
Для HTTPS-сценария дополнительно проверьте hosts и CA в следующем разделе.

### «Не удалось загрузить данные» / «Нет соединения с сервером»

1. Проверьте backend с хоста:
   `curl -fsS http://127.0.0.1:8000/api/v1/regions`.
   Если ответа нет, проверьте локальные контейнеры (`docker ps`) или процесс
   backend по его инструкции запуска.
2. Проверьте выбранный адрес API. По умолчанию — `http://10.0.2.2:8000`;
   значение `EXPO_PUBLIC_API_URL` при запуске Metro может его переопределить.
3. Посмотрите ошибки приложения:
   `adb logcat -d -t 500 -s ReactNativeJS:E AndroidRuntime:E`.
   `401` означает необходимость повторного входа.
4. Если выбран HTTPS dev-стенд: `Unable to resolve host` требует подготовки
   hosts, а `SSLHandshakeException` — проверки системного CA. Локальный HTTP
   не использует эти настройки.
5. После изменения адреса перезапустите Metro и приложение. После изменения
   доверия HTTPS также перезапустите приложение: OkHttp кэширует соединения.

### Эмулятор зависает, ADB показывает `device`

Статус `device` не подтверждает работу интерфейса Android. В предыдущем
окружении Emulator 35.5.10 / `afaci_rooted` shell отвечал, но снимки экрана
и UI-команды зависали. Перезапуски и смена рендеринга не помогли; точная
первопричина не установлена.

На 2026-11-01 Emulator обновлён до 37.2.13 и создан отдельный
`afaci_qa_stable` с 4 ГБ RAM. Пять последовательных снимков и ручные сценарии
калькулятора прошли без зависаний. Длительная стабильность ещё наблюдается;
старый AVD и его данные сохранены.

Проверьте версию (`emulator -version`), свободное место, RAM AVD и холодный
запуск командой выше. Для диагностического снимка можно ограничить ожидание:

```bash
adb shell 'timeout 5 screencap -p /sdcard/qa-screen.png'
```

Тайм-аут означает, что ручной QA не завершён. Не очищайте данные AVD ради
повторной проверки без отдельного решения; используйте отдельный AVD.

### Дев-стенд не виден из приложения

Этот раздел относится только к альтернативному HTTPS-подключению.

Проверить, что CA лежит в namespace, из которого форкаются приложения, —
именно здесь ломалось (см. [`ERROR.md`, п. 13](../ERROR.md)):

```bash
HASH=$(openssl x509 -inform PEM -subject_hash_old -in assets/certs/caddy_root.pem | head -1)
ZPID=$(adb shell ps -A | awk '/zygote64/{print $2; exit}')
adb shell su 0 nsenter -t "$ZPID" -m ls /apex/com.android.conscrypt/cacerts/$HASH.0
```

Файл должен существовать. Если `No such file` — эмулятор перезагружался,
повторите `./scripts/dev-emulator.sh`. Если файл есть, а рукопожатие всё
равно падает, проверьте отказы SELinux:

```bash
adb logcat -d -b all | grep "avc: denied" | grep cacerts
```

Отказы с `tcontext=u:object_r:appdomain_tmpfs:s0` означают, что сертификаты
не переметили; это делает `dev-emulator.sh` — перезапустите его и приложение.

Если CA перевыпущен на хосте, обновите `assets/certs/caddy_root.pem` (нужен
именно **корневой** CA Caddy — промежуточный он перевыпускает еженедельно) и
снова прогоните скрипт.

### Красный экран `Unable to load script`

Приложение не достучалось до Metro на `10.0.2.2:8081`.

- Metro запущен? `curl http://localhost:8081/status`.
- **Не добавляйте `--localhost` к `npm start`.** С этим флагом Metro слушает
  только IPv6-loopback `[::1]:8081`, а эмулятор ходит на IPv4-loopback хоста
  `10.0.2.2`. `adb reverse tcp:8081 tcp:8081` не нужен.
- Не держите два Metro на одном порту: `lsof -nP -iTCP:8081 -sTCP:LISTEN`.

Если в логе висит `Couldn't connect to packager, will silently retry`, а
экран показывает старые данные — приложение работает на прошлом бандле;
поднимите Metro и перезапустите приложение.

### Сборка падает на «No development build»

```
No development build (kg.afaci.afaci_mobile) for this project is installed
```

Ожидаемое поведение, не поломка. В проекте нет `expo-dev-client`, поэтому
deep link `afaci://expo-development-client/?url=...`, которым Expo CLI
открывает приложение, обрабатывать некому. Плюс у debug-сборки
`applicationId` с суффиксом `.dev` (config plugin
`plugins/with-debug-application-id-suffix.js`), а CLI ищет пакет из
`app.config.ts`, то есть без суффикса. APK уже установлен — запускайте
`npm run android:launch`.

По той же причине `npm start` запускается **без** `--dev-client`.

### `Activity class ... does not exist`

Класс активити — `kg.afaci.afaci_mobile.MainActivity`, а пакет —
`kg.afaci.afaci_mobile.dev`: суффикс есть у applicationId, но не у имени
класса. Готовая команда — `npm run android:launch`. Проверить вручную:

```bash
adb shell cmd package resolve-activity --brief kg.afaci.afaci_mobile.dev | tail -1
```

### `adb root` не даёт root

`adb shell id` показывает `uid=2000(shell)` — AVD создан на образе Google
Play. Пересоздайте его на образе **Google APIs** (userdebug) под именем
`afaci_rooted`.

### Не записывается `/system/etc/hosts`

Эмулятор запущен без `-writable-system`. Закройте его и стартуйте командой
из [HTTPS-сценария](#альтернатива-https-dev-стенд).

### Подключено несколько устройств

`adb` ругается `more than one device/emulator`:

```bash
adb devices
export ANDROID_SERIAL=emulator-5554
```

### После перезагрузки эмулятора всё «отвалилось»

Для HTTPS dev-стенда монтирование CA живёт в tmpfs и не переживает ребут. Порядок:
`adb root` → `./scripts/dev-emulator.sh` → перезапуск приложения. Пересборка
APK не нужна. Для локального HTTP hosts и CA не требуются — проверьте backend, Metro и сессию входа.

### После смены зависимостей

Изменились нативные пакеты, `app.config.ts`, `plugins/` или `android/` —
нужна новая сборка: `npm run android -- --device emulator-5554`, затем
`npm run android:launch`. Чистый prebuild:
`npx expo prebuild --platform android --clean`.

## Структура

```text
afaci_mobile/
  app/                     # expo-router
    (auth)/login.tsx       # вход
    (tabs)/                # главная, база, калькулятор, рецептуры, профиль
    admin/                 # дашборд, продукты и нутриенты
  src/
    modules/               # фичевые модули (home, catalog, products, …)
    shared/
      api/                 # клиент, модели, типы OpenAPI
      session/             # Zustand-сессия, токен, права, редиректы
      lib/                 # форматирование ru-RU, сом, cn
      theme/               # цвета для API навигации
      ui/                  # gluestack-ui + kit (Screen, Card, Button, …)
    global.css             # семантические токены (светлая/тёмная тема)
  plugins/                 # Expo config plugins
  scripts/                 # dev-emulator.sh
  android/                 # prebuild, коммитится
  assets/
    images/                # иконки и splash приложения
    certs/                 # корневой CA dev-стенда
  app.config.ts
```

Сессия хранится в `expo-secure-store`, серверные данные — в TanStack Query,
локальное состояние — в Zustand. UI использует gluestack-ui v5 и NativeWind v5.
Формулы Липатова и конвертация единиц выполняются только на backend через
`/compute`. Самостоятельной регистрации в приложении нет — инвайт-модель.
Пользователей создаёт только администратор через `POST /users`;
публичный `POST /auth/register` удалён.

## Сессия и навигация

- Токен — `expo-secure-store` (ключ `afaci_token`), в памяти дублируется для
  синхронного доступа из API-клиента.
- `GET /api/v1/auth/me` при старте восстанавливает сессию; недействительный
  токен стирается, приложение открывается как гость.
- Сетевая ошибка или 5xx при восстановлении сохраняет токен и показывает
  кнопку повтора. Если SecureStore не смог удалить токен при выходе, повтор
  сначала завершает удаление; старый вход не восстанавливается.
- 401 на запросе с токеном → разлогин и `queryClient.clear()`.
- Обычный 403 показывает ошибку прав, сохраняя сессию; 403 от `/auth/me`
  закрывает недоступную сессию.
- Главная, «О нас» и база открыты гостям. Калькулятор, рецептуры, профиль и
  админка требуют входа: гость переходит на `/login?next=...`. После входа
  `next` проверяется по белому списку (`src/shared/session/next-route.ts`).
- Авторизованный пользователь не остаётся на `/login`. Logout очищает кэш;
  запоздалые ответы старой сессии не меняют новую.

## Готовность

Этапы 1–6 реализованы и приняты с ограничениями QA, указанными в плане.
Главная содержит карточку базы в ширину карточек «Инструментов» и секцию
«Оптимизация рецептур»; прежний блок «Изучайте состав продуктов» и кнопка
«О нас» с главной удалены (этапы 15–18). В публичной карточке продукта
«Химический состав» идёт первым среди групп нутриентов (этап 19).

Выбор эталонного белка в калькуляторе не содержит поиска (этап 20).
Окно информации показывает документ-источник, авторов, год, страницу/таблицу
и кнопку «Открыть документ» (этап 21). Данные берутся из API, при отсутствии
источника показано «Источник не указан». Предпочитается `pdf_url`, иначе
`url`; документ передаётся внешнему браузеру или PDF-приложению. Ошибка
передачи отображается в AFACI, ошибки последующей загрузки — во внешнем
приложении. Источники Young & Pellett и FAO успешно открыты на Android.

**Этап 22 принят пользователем 2026-11-01 с указанными ограничениями QA.**
В обычном калькуляторе добавление ингредиента перенесено в плавающую кнопку
над навигацией, сохранение — в иконку рядом с «Рассчитать». Кнопки открытия
сохранённой рецептуры и оптимизации стоимости убраны из обычного калькулятора.
Красный outline-сброс и удаление ингредиента требуют подтверждения.
Отдельные экраны оптимизации сохраняют собственные действия.

Наличие локального кода не означает его слияние или завершение приёмки.
Актуальные статусы, ограничения и следующие задачи — в
[`plan/mobile.md`](../plan/mobile.md); следующие этапы автоматически не начинаются.

## Ручная проверка этапа 1

1. Без входа открыть главную и базу; открыть калькулятор и рецептуры —
   должна появиться форма входа.
2. Проверить пустую форму, неверный email, показ/скрытие пароля и ошибку
   неверного пароля. Регистрации в интерфейсе нет.
3. Войти существующей учётной записью; после входа открывается запрошенный
   защищённый раздел. Внешний URL в `next` игнорируется.
4. Перезапустить приложение — вход восстанавливается. Открыть `/login` —

## Dev-стенд из эмулятора

Схема из [`ERROR.md`, п. 10 и 13](../ERROR.md): эмулятор не видит хостовый
`/etc/hosts`, а сертификат dev-стенда подписан локальным CA Caddy.
Всё делает `./scripts/dev-emulator.sh`:

1. `adb root` и `adb remount`;
2. `10.0.2.2 api.foodcraftsl.lab` в `/system/etc/hosts`;
3. корневой CA Caddy в системный store. На Android 14+ (API 34+) store
   переехал в APEX, поэтому `tmpfs` монтируется поверх
   `/apex/com.android.conscrypt/cacerts` — живёт до перезагрузки.

Про третий пункт важны две детали, без которых приложение CA не видит:

- монтировать нужно в mount namespace init **и каждого** zygote
  (`nsenter -t <pid> -m`): приложения форкаются от zygote и наследуют его
  namespace, а не namespace init;
- скопированные в tmpfs файлы получают контекст SELinux `appdomain_tmpfs`,
  и `untrusted_app` запрещено их открывать, поэтому скрипт переметит их в
  `u:object_r:system_security_cacerts_file:s0`.

Обе ошибки дают один и тот же симптом — `SSLHandshakeException: Trust anchor
for certification path not found` при живом бэкенде.

OkHttp (на нём работает `fetch` в RN) не доверяет пользовательским
сертификатам и не читает `network-security-config` в debug-сборке, поэтому
debug-конфиг намеренно не используется.

В текущем локальном коде рядом с ранжированием находится «Оптимизация» с двумя режимами:
`/saved/optimization/basic` и `/saved/optimization/cost`. Оба используют

стоимости процент не рассчитывается. Сохранить можно найденный состав
новой рецептурой или обновить исходную; базовый режим сохраняет ранее
указанные цены, не используя их при оптимизации.

В админке доступны категории, подкатегории, регионы, единицы измерения,
типы и названия нутриентов. Универсальный экран содержит поиск, обновление
свайпом, создание, редактирование и удаление с подтверждением. Подкатегория
обязательно связана с категорией, название нутриента — с типом. При ошибке
сервера форма сохраняет значения; после успеха обновляются словари и каталог.
Admin/editor могут изменять записи, viewer видит только чтение по прямому
маршруту. API проверяет роль для операций изменения.

Ручная проверка словарей:

- Под admin и editor создать временную запись в каждом из шести словарей,
  найти её по названию, переименовать и повторно открыть форму.
- Для подкатегории выбрать категорию, для названия нутриента — тип;
  проверить сохранение связи после повторного открытия и смену группы.
- Пустое название и отсутствие обязательной группы не отправляются.
  Повторное название в одной группе показывает ошибку; форма не очищается.
- Отменить удаление; затем удалить временные записи. Попытка удаления
  используемой записи показывает ошибку связей без ложного успеха.
- Под viewer проверить скрытые действия изменения и отказ API (403);
  без токена операции изменения возвращают 401. Публичное чтение сохранено.
- Проверить сеть/повтор, клавиатуру, Android Back, TalkBack, обе темы,
  небольшой экран и увеличенный шрифт.

Изменение типа в справочнике названий нутриентов меняет только сам справочник.
Тип в ранее сохранённых строках состава продуктов остаётся прежним;
синхронизация существующих данных в этап 6 не входит.

## Пользователи — этап 6

Раздел `/admin/users` доступен только admin: список с поиском по имени/email,
фильтрами роли и статуса, создание и редактирование пользователя. Статус
фильтруется на клиенте по активности и сроку доступа, поскольку API принимает
только поиск и роль. Дата и время выбираются системными Android-диалогами;
показан часовой пояс устройства, сервер получает UTC ISO. Безлимитный доступ
сбрасывает срок. При создании можно потребовать смену временного пароля.
Смена роли и блокировка собственной учётной записи запрещены;
имя и будущий срок собственной записи доступны для изменения, как в API.

Ручная проверка пользователей (факт прохождения — в мобильном плане):

- Под admin открыть список, проверить поиск кириллицей/email, все роли и
  статусы, пустой результат, сетевую ошибку с повтором и обновление свайпом.
- Создать только временную QA-запись: проверить пустое имя, некорректный email,
  пароль короче шести символов и дубликат email. Ошибка сохраняет введённые поля.
- Выбрать дату и время в будущем, проверить часовой пояс и сохранённый срок;
  отменить каждый диалог. Проверить запрет прошедшего времени и переключение
  безлимитного доступа при создании и редактировании.
- Изменить имя, роль и срок QA-записи, открыть её повторно. Заблокировать,
  проверить статус и отказ входа, сохранность групп и рецептур, затем
  разблокировать и проверить восстановление доступа. Безвозвратного удаления нет.
- У собственной записи проверить недоступность смены роли и блокировки;
  изменение имени должно обновить профиль без повторного входа.
- Под editor/viewer проверить прямые ссылки списка и формы: они возвращают
  в админку; гости направляются на вход. Backend также требует admin.
- Проверить обе темы, узкий экран, крупный шрифт, клавиатуру, Android Back,
  TalkBack, повторную отправку и выход из сессии во время запроса.

Проверки кода не заменяют эти сценарии с действующей административной
учётной записью. Нативный date-time picker требует пересборки Android APK.

## Версии приложения

Экранов версий и загрузки APK в мобильном приложении нет: версиями управляют
только через API backend или веб-интерфейс администратора.
`expo-document-picker` удалён; после этого нужна пересборка Android APK.

Создание продукта состоит из двух шагов: основные данные → отдельный экран
нутриентов с добавлением, редактированием и удалением записей. «Готово»
открывает карточку продукта. Выбор справочников открывается нижней панелью
с поиском и безопасными отступами. Дополнительный ручной QA: проверить
выбор нутриента внутри диалога, завершение второго шага и возврат назад.

Этап 6 принят пользователем 2026-10-27 в текущем виде. Известные
ограничения ручного QA и Expo Doctor сохранены в мобильном плане.
