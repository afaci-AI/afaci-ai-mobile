# AFACI Mobile (Flutter)

Мобильный клиент (Android + iOS) к бэкенду FastAPI (`../afaci`). Реализует
пользовательские сценарии «site»-фронтенда: авторизация, калькулятор пищевой
и биологической ценности, сохранённые рецептуры и их ранжирование.

Построен по плану [`MOBILE_FLUTTER_PLAN.md`](../Планы%20/MOBILE_FLUTTER_PLAN.md).

## Запуск

Базовый URL API задаётся через `--dart-define`. На Android-эмуляторе адрес
локального бэкенда — `10.0.2.2` (значение по умолчанию), на iOS-симуляторе —
`localhost`.

```bash
flutter pub get

# Android-эмулятор (по умолчанию http://10.0.2.2:8000)
flutter run

# iOS-симулятор / другой адрес
flutter run --dart-define=API_BASE_URL=http://localhost:8000

# Прод
flutter run --dart-define=API_BASE_URL=https://api.example.kg
```

Бэкенд: из каталога `../afaci` — `uvicorn main:app --reload` (порт 8000).

## Архитектура

Слои зеркалят backend Clean Architecture (см. корневой `CLAUDE.md`):

```
lib/
  core/      — http-клиент (dio), env, ошибки, secure-хранилище токена
  domain/    — entities + fromJson, без Flutter
  data/      — api-клиенты по фичам (auth, products, calculator, saved, ranking)
  app/       — DI (riverpod), роутинг (go_router) с гардом, тема, session
  features/  — модуль на фичу: auth, products, calculator, saved, ranking, home
```

**Расчёт — только на сервере.** Формулы Липатова и конвертация
мг → г/100 г белка живут в backend `domain/calculator/formulas.py`. Клиент их
не дублирует (та же причина, что в `CLAUDE.md`): отображает ответ `/compute`.

**Поиск продуктов** идёт через `GET /table/products?product=...` (ILIKE на
сервере). Регистронезависимость кириллицы — ответственность бэкенда
(локаль C), клиент регистр не «чинит».

## Навигация и доступ (как на сайте)

Нижняя навигация — 4 вкладки: **База данных**, **Калькулятор**, **Рецептуры**,
**Профиль**.

- **База данных** открыта без входа — список продуктов с поиском и фильтрами
  (категория, регион) и карточка продукта с нутриентным составом. Список
  грузится постранично (бесконечная подгрузка по 10 элементов через
  `limit`/`offset`, следующая порция — при доскролле до 7-го элемента),
  чтобы не тянуть весь справочник разом.
- **Калькулятор**, **Рецептуры** и **Профиль** закрыты `AuthGate`: гостю
  показывается приглашение войти/зарегистрироваться (продукты доступны всем,
  остальное — после регистрации).
- **Ранжирование** и **Оптимизация стоимости** вынесены внутрь вкладки
  «Рецептуры» как под-вкладки (Сохранённые / Ранжирование / Стоимость), чтобы
  не перегружать нижнюю навигацию.

Стилистика (синий primary, холодный светло-серый фон, радиусы, бренд-иконка
AFACI) повторяет веб-сайт (`afaci-frontend`, `globals.css`).

## Авторизация

JWT (HS256, срок 7 дней), refresh-токена нет. Токен в `flutter_secure_storage`,
подставляется интерсептором как `Authorization: Bearer <token>`. На 401 токен
стирается и пользователь уходит на `/login` (гард `go_router`).

## Отступление от плана

План рекомендовал `freezed` + `json_serializable` для DTO. Здесь использовано
**ручное иммутабельное маппирование** (`fromJson`/`toJson`) без codegen —
чтобы не тащить шаг `build_runner` в сборку. Контракт и поведение идентичны;
при желании DTO легко перевести на freezed позже.

## Сборка релиза

- Android: `flutter build appbundle` (нужен keystore).
- iOS: `flutter build ipa` (нужны bundle id и подпись).
- Для прод-сборки указать `--dart-define=API_BASE_URL=https://...`.
  Dev-послабления для HTTP (`usesCleartextTraffic` на Android,
  `NSAllowsLocalNetworking` на iOS) на HTTPS не влияют.

## Оптимизация стоимости

Вкладка «Стоимость» (`features/optimize/`): пользователь добавляет
продукты-кандидаты с ценой (сом/кг) и границами массы `[min; max]`,
опционально задаёт ограничения качества (БЦ ≥, КРАС ≤), и сервер
(`POST /calculator/optimize-cost`, SLSQP) находит дешевейший состав на 100 г.
Результат: стоимость 100 г, оптимальные массы (имена берутся из вложенного
`report`) и переход к полному отчёту. Неразрешимая задача → бэкенд отдаёт 422
с человекочитаемой причиной, показывается дословно.
